# Agnes 产品图生成（外观 / 效果 / 爆炸）

> 相关技能：`agnes-image`（Agnes 图像服务的原始 API 调用：文生图 / 图生图 / 视频）。
> 本技能不管 API 怎么调，只管**一组产品图之间怎么保持一致**以及**什么时候必须停下来等人**。

## 这条链要解决什么

不是「画出几张好看的图」，而是**产出一组互相一致的图**，让下游（结构建模、硬件装配）
能拿它们当同一台产品的形状来源。最常见的翻车方式是：四次调用各画各的，
结果 render-01 是圆角矩形，render-02 变成方形带把手 —— 结构阶段照谁建都不对。

核心手段只有两条：**串行出图** + **后一张以前一张为参考做图生图**。

## 执行顺序（严禁并行、严禁一次写完所有 prompt 再批量调用）

| 步 | 调用 | 说明 |
|---|---|---|
| 1 | `generate_product_image(kind="render", prompt=<完整产品描述>)` | **基线**。第一张是文生图，产品长什么样由它定死 |
| 2 | 等它返回、确认文件落盘（看返回里的路径与体积） | 没落盘就别往下走 |
| 3 | `generate_product_image(kind="render", prompt=<只写要改成什么样>)` | 第二张起自动以**上一张**为参考做图生图 |
| 4 | 需要更多视角 continue 第 3 步 | 每次只改一个变量（视角 / 场景 / 光位） |
| 5 | `generate_product_image(kind="exploded", prompt=<只写怎么拆>)` | 爆炸图始终以**第一张**外观图为参考，别传 reference |
| 6 | `confirm_with_user(stage="10_appearance", ...)` | **停下来等人确认**，不许自己判断「挺好」就往下跑 |

## Prompt 怎么写

### 第一张（文生图，基线）—— 必须写满

形态 / 比例 / 主色（HEX）/ 材质与工艺 / 可见特征的位置（屏幕、按键、接口在哪个面）。
**必须带可量化的外形信息**：长宽高比例、圆角大小、分件方式。
原因：这张图的 prompt 会自动存档进 `10_appearance/prompts.json`，
结构阶段 `text_to_cad` 就是拿它做 3D 建模的形状约束。
写「科技感十足的小夜灯」这种形容词，下游只能瞎猜尺寸。

### 第二张起（图生图）—— 只写差异

```
参考图里这同一台产品，改成 45 度侧视，放在浅灰亚麻布上，侧逆光。
严格保持参考图中同一产品的外形、比例、材质与配色，只允许改视角、构图与背景。
```

第二行是**一致性锚**，必须写。不写的话模型会把同一产品画成两代外形。

### 爆炸图 —— 只写怎么拆

零件清单（按装配顺序）、每个零件的材质与颜色、沿装配轴分离的排列方式、
是否带装配引导线。不要重复描述产品外形，参考图已经定死了。

## 文件命名

- 工具会自动顺延编号：`render-01.png` → `render-02.png`，爆炸图 `exploded-01.png`。
- **不要指定已存在的文件名**：同图覆盖会毁掉参考图链（下一张就没得参考了）。
- 图片只能由 `generate_product_image` / `render_product_views` 产出。
  用 `save_artifact` / `write_file` 写 `.png` 会被平台拒绝 ——
  这是有教训的：出图成功后有人把 739 KB 的真图覆盖成 11 字节的 `placeholder`，
  用户看到的现象就是「图生成后被删了」。

## 失败怎么分诊

| 返回里出现 | 判断 | 动作 |
|---|---|---|
| 鉴权失败 / 401 | 密钥或网关配错 | **立刻停止调用**，改走 `render_product_views` 出工程视图兜底 |
| 限流 429 | 额度窗口 | 换一版更中性的 prompt 重试，最多 2 次 |
| 超时 / 连接重置 | 网络或 CDN 被拦 | 工具内部已走 base64 直出与 TLS 三级降级；仍失败就重试 1 次 |
| 内容审核 | prompt 触发 | 去掉敏感词重写，不要硬重试 |

拿不到 AI 图时**不允许无图交付**：至少要有
`orthographic.svg`（手写三视图）+ `appearance.md` 里注明「AI 图不可用，以三视图 +
结构阶段工程视图为形状来源」。

## 收尾必须做

1. 把图片以 Markdown 引用插进 `appearance.md`：`![产品渲染](10_appearance/render-01.png)`
2. 调用 `confirm_with_user(stage="10_appearance", summary=…, files=…)`，
   summary 写清：出图几张、外形尺寸与比例、主色、与 PRD 的差异。
3. 返回「需修改」就按反馈重做，**改完再调一次** `confirm_with_user`。
