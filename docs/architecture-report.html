Architecture & Tech Stack

一句话需求 → 六阶段自主设计流水线 → 可交付的工程产物

本项目是一套面向智能硬件的多智能体设计流水线：用户输入一句产品需求后， 系统先做需求补全问卷，再由主智能体按强相关的串行 DAG依次派单给六个专业子智能体， 产出外观渲染图、结构 STEP/STL、电路原理图/PCB/Gerber、固件代码与交叉评审报告， 全程通过 SSE 向前端实时回传事件流，产物落盘为可直接使用的工程文件。

1 · 系统定位 what & why

一句话需求到工程产物的端到端自动化，中间每一步都有可验证的落盘物。

输入端：需求补全

「补全需求」返回 6–10 项待确认清单（场景/指标/尺寸/供电/主控/成本…），带充分度评分与「为什么问这个」。模型不可用时自动降级为内置通用模板，流程永不断。

中段：六阶段流水线

需求 → 外观 → 结构 → 硬件 → 固件 → 评审。每阶段声明 depends（上游）与 requires（开工前磁盘上必须已存在的产物），门禁由磁盘产物反推，模型嘴上说没说不算数。

输出端：可交付产物

渲染图/三视图、STEP + STL + 爆炸图、原理图 + PCB + Gerber + BOM、.ino 固件、一致性评审。EDA 产物可直接发板厂，.epro 双击即开。

设计取向：整条链路的判据一律以磁盘为准。阶段是否完成看契约产物集是否齐全； 运行是否还活着看 updated_at 是否推进；文件清单扫目录而不是读事件流 —— 子智能体常绕过 save_artifact 直接写文件，事件流会漏掉一半。

为什么是这些选择

全 OpenAI 兼容协议

所有 LLM 调用统一 /chat/completions，服务商（7 家预置 + 自定义）只改 base_url 与 key。密钥优先级：前端设置 → .env（按 base_url 匹配）→ 演示模式。

EDA 内核零依赖

不引 kicad python 包、不引 EasyEDA SDK，网表/封装/PCB/Gerber 全用标准库算出来 —— 可离线跑、可单元测试、不随第三方版本漂移。

CAD 走云端沙箱

本机 8GB 并发建模实测必崩；OCP 装包 700MB 且限制 x86_64。AGENT_CAD_RUNTIME=auto 优先 E2B，服务器保持轻量。

SQLite 而非 Postgres

单机单进程、数据量小（会话/事件/清单）、零运维；代价是不能多副本 —— 已在 compose 里显式限制为单实例。

5 · 智能体编排 orchestration

一个主智能体 + 七个角色子智能体；工具按角色裁剪，范式决定预算与推理策略。

角色矩阵

角色职责工具数关键约束
requirements-analyst模糊需求 → 工程规格：功能清单、场景、约束、验收标准4先于一切设计开工
industrial-designer形态语义、CMF、人机界面、三视图 SVG、渲染提示词6出图一条消息只派一个任务
mechanical-engineer分件、壁厚拔模、装配序列、DFM，出 STEP/STL + 爆炸图7几何推演先落 model.py 再调工具

integration-reviewer四套方案交叉评审：尺寸/引脚/BOM/工艺2只出结论，不重复造物

踩过的坑：deepagents 会自动补一个内置 general-purpose 角色，其工具 = 文件中间件 + 主智能体工具 （本项目只有 confirm_with_user）。改派它只会回一句「没有 build_structure」，比原角色失败更糟。 现在显式提供同名 spec 覆盖内置，并给全套工具；同时主提示词规定补派只能补同一角色。

主智能体的硬约束

  • 串行派单：出图 / 建模一条消息只允许一个 task —— 并行派单会让参考图链断掉（后一张拿不到前一张做参考）。
  • 补派同角色：换人兜底优先级低于原角色；未完成判据有三条 —— 报工具不可用 / 回交空或只回「门禁通过」/ 承诺的文件没落盘。
  • 补派上限：同一阶段最多补派 2 次，第 3 次标注缺项进下一阶段（这是曾经把步数烧光的直接原因）。
  • 中文硬约束：含深度思考文本在内一律简体中文，否则会漂到波斯语/阿拉伯语。
  • 别在思考里做长篇数值推演：先落文件 —— 2.4 万字几何推演被截断而未落盘的教训。

并发铁律：工具在线程池里并发跑，而 CPython 的 _find_and_load 是先拿子模块锁再导父包， 并发「一个导包根、一个导子模块」会成环 → _DeadlockError（实测约 10% 命中）。 因此统一走 tools._mod(name, attr)（首次导入串行 + 启动时预热），禁止在工具函数里裸写「用到才 import」。

7 · 护栏与容错 guardrails

护栏的目的不是把模型锁死，是「别把已确认的东西重做一遍」—— 任何拒绝型护栏都要配可执行的下一步 + 熔断。

机制触发行为状态语义
阶段护栏在 DONE/CONFIRMED 阶段重做拦 done 1 次 / confirmed 2 次 后放行一次自我纠错并把状态退回一档；多产物工具在「目标文件不存在」时直接放行REVISED
工具预算按代价加权累计超预算廉价只读 0.25、出图/CAD 1.0；只读工具阈值高一个量级budget
时限超过档位 max_seconds中止并保留产物，可自动续跑（复用同一工作区，最多 N 轮）timeout
步数上限LangGraph 撞 recursion_limit捕获后先收口工具卡片再转抛，按中止处理（不是故障），走同一条自动续跑通路steps
目标达成契约产物齐全按「完成」收尾；产物已够时不显示「超出预算中止」done
用户停止前端点停止cancel_requested 轮询点，协作式退出cancelled
429 配额守卫网关限流预防式降速（快撞了先慢）+ 撞到后自动关深度思考（思考占总输出 75–85%）—
CAD 几何自检模型体积≤0 / 任一维>500mm / 远超声明外形判失败而不是当成功锁阶段—
人机闸门每阶段结束（可 AGENT_HUMAN_GATE=0 关闭）落 _human_review.md，用户批准 / 打回带意见CONFIRMED
服务重启回收进程启动reap_orphans() 把上次没跑完的运行如实标记，不留 running 僵尸—
设计原则：「成功」判据必须包含产物自检，不能只看「没报错」。 曾经把 100×100×341mm 的畸形模型当成功并锁死阶段，后面想改又被护栏拦 —— 8 次调用全废，用户只能手动取消。

网络层与环境的坑（已内置规避）

  • IPv4 优先：DNS 双栈下 Python 串行尝试且 IPv6 排前，本机 IPv6 出口高延迟 → 表现为「网关间歇性不可达」。进程级 patch 把解析结果排序（不是过滤），AGENT_IPV4_FIRST=0 可关。
  • 外部 CLI 只探测一次：uvx 起一次约 21s，且并发会撞自己的缓存锁（失败特征是 returncode≠0 且 stdout/stderr 全空）→ 探测出解释器绝对路径后固化，并加全局锁串行化。
  • 探测失败带 TTL：成功可永久缓存，失败只信 120s，否则一次抖动让能力在整个进程生命周期里判死。

9 · EDA 领域内核 agent/eda

两个事实源 + 多种投影产物；改一处就要重出所有产物。

事实源一：netlist.json

电路连接。端点必须是「位号.引脚名」格式（模型常写成 C2正极 漏点号，会被当裸网络名丢掉，导致元件「没有任何连线」→ PCB 无飞线）。

事实源二：board.json

板框与布局约束。板中心为原点、mm、Y 向下，板型支持 rect / rounded_rect / circle / ellipse / polygon。它是 PCB 外形的机器可读来源（曾只写在 markdown 表格里，三个会话三种写法，程序读不了）。

子模块职责要点
netlist.py规范化 + 并查集聚网极性别名表 + 右剥极性词 + 端点字符串回写
board.py · parts.py板框解析 / 器件尺寸与布局接口先占边 → 主控居中 → 其余从中心向外找空位；三级放宽间距
lib.py立创官方元件库对接符号 1:1、封装 ×10 单位差；种类冲突必须在 fetch() 之后再判；403 有退避
symbols.py · sch.py符号生成 / 原理图段排版A4 = 1170×825（1/100 英寸），排版必须卡在框内
kicad.py.kicad_sch / .kicad_pcb符号必须内嵌 lib_symbols 并同时出 sym-lib-table
pcb.py板框 / 布局 / 安装孔 / 铺铜只布局不布线；POLYGON 焊盘会让导入器段错误 → 一律降级成矩形
gerber.pyGerber / 钻孔 / 坐标KiCad 10 铜层命名两种都要认（-top_cu.gtl 与 -F_Cu.gtl）
easyeda.py.epro writer（zip 容器）PCB 段单位 mil、坐标必须为正；行长度错一个字段就不渲染
preview.py纯 Python 渲染原理图 SVGRECT 是两个角点、POLY 点是扁平数组、PIN 的 (x,y) 是外接点

10 · 部署架构 deployment

两条路径：Docker Compose（推荐）与裸机 systemd。

worker

Python 3.13 slim 镜像，AGENT_HOST=0.0.0.0，端口 8001，内存限 2G；挂载 data/（要备份）与 workspace/（按需清理）；healthcheck 打 /health。

web

Next.js 生产构建，AGENT_WORKER_URL=http://worker:8001（走 compose 内网，浏览器不直连），依赖 worker 健康后才起。

nginx

80（+可选 443）入口，转发 /api/stream/* 必须 proxy_buffering off，否则 SSE 被缓冲成一次性下发。

  • 实例架构必须 x86_64：OCP 只有 x86_64 manylinux wheel（ARM 倚天 710 装不上）；但推荐直接走 E2B 云端建模，服务器不装 OCP。
  • 单副本：store 用 SQLite 且连接是模块级单例，多副本会互相抢库。
  • 密钥只写 .env：config.py 用 override=True 加载，避免 shell 残留同名变量静默顶掉（曾导致「换了 key 还是 401」）。
  • 裸机方案：deploy/bare/ 提供两个 systemd unit + 宿主机 nginx 配置 + setup.sh；日常运维用 deploy/agentctl.sh。
